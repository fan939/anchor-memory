# v1.14 — Salient recall, consistent errors, and safe maintenance

## Fixed

- Business failures now produce MCP tool errors (`isError: true`) over both
  stdio and HTTP instead of looking like successful structured content.
- `wakeup` and ordinary Reflection retrieval exclude retracted/abandoned data.
- The HTTP Reflection adapter no longer leaks its internal `invoke` closure into
  `draft_reflection` or `search_reflections` arguments.
- MCP schemas now advertise real enums, ranges, conditional Core confirmation,
  and a three-query cap for targeted recall.

## Added

- Recall-only `salience`, `motifs`, `state`, `unresolved`, and
  `open_questions` fields, plus the unified `update_memory_metadata` tool.
- Explicit typed graph relations, including directional `supersedes` and
  symmetric `contradicts`, with auditable `get_links` reads.
- Search debug components for semantic, graph, salience, recency, feedback,
  state, and final ranking explanation.
- Dual-store `reconcile` repair, synchronized retraction/deletion, and
  maintenance run audit records.
- `dream_pass` dry-run previews and caller-provided idempotency IDs. MCP uses
  safe defaults (`dry_run=true`, no auto-discovery, no bundled-memory split).

## Migration and deployment

SQLite columns and the `maintenance_runs` table are added automatically when
Anchor starts. Back up the data directory before deploying, run `reconcile`
without repair first, and inspect a `dream_pass` dry run before applying one.
